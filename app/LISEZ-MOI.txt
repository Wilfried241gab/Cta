CTA LAMBARÉNÉ — APPLICATION DE GESTION, VERSION FINALE 14 (XAMPP + MySQL + phpMyAdmin)
======================================================================================

NOUVEAUTÉS DE CETTE VERSION
  - Version finale : plus de données fictives ni de boutons « démo/réinitialiser ». La base démarre vide.
  - Comptes gérés par le SERVEUR : mots de passe hachés (password_hash) et jamais envoyés au navigateur ;
    le serveur contrôle les droits de chaque rôle (un compte caisse ne reçoit même pas les données de la pharmacie).
  - Journal d'audit écrit par le serveur, en ajout seul, chaîné par empreintes ; il enregistre aussi les
    consultations de dossiers patients, les refus d'accès, les connexions et échecs.
  - Numéros de reçu attribués par le serveur : plus de doublon possible, même avec plusieurs caisses.
  - Démarrage plus rapide : fichiers découpés, versionnés, compressés et mis en cache ; plus de requête bloquante.
  - Sauvegarde CHIFFRÉE quotidienne (AES-256) + copie hors de l'ordinateur + restauration complète.
  - Version de schéma, journal d'erreurs serveur (logs\cta_erreurs.log), page etat.php avec « points à corriger ».

CONTENU DE L'ARCHIVE   (dossier « cta » à copier dans c:\xampp\htdocs\)
  index.php, app.html, assets\     l'application
  api.php, common.php              serveur (droits, comptes, journal, reçus)
  config.php                       réglages (base, mot de passe provisoire, HTTPS, copie externe...)
  etat.php                         contrôle de l'installation
  base_cta.sql                     base à importer dans phpMyAdmin
  install_database.bat             installation automatique de la base + utilisateur MySQL dédié
  installer_sauvegarde.bat         planifie la sauvegarde chiffrée de 13h30 chaque jour
  phpmyadmin_bloquer.bat / phpmyadmin_debloquer.bat   ferment / rouvrent phpMyAdmin (renomment son dossier)
  sauvegarde.bat / sauvegarde.php  sauvegarde chiffrée    restaurer.bat / restaurer.php  restauration
  durcir_mysql.bat                 mot de passe root + utilisateur dédié (voir DURCISSEMENT.txt)
  DURCISSEMENT.txt                 sécuriser le serveur (à lire avant de mettre en service)

INSTALLATION (nouvelle machine)
  1. XAMPP : démarrez Apache ET MySQL.
  2. Copiez « cta » dans c:\xampp\htdocs\ (vous obtenez c:\xampp\htdocs\cta\index.php).
  3. Double-cliquez install_database.bat : il crée la base, l'utilisateur MySQL « cta » (choisissez un mot de passe
     de 12 caractères minimum) et met config.php à jour.
     Alternative : phpMyAdmin > Importer > base_cta.sql, puis réglez config.php à la main.
  4. Ouvrez http://localhost/cta/etat.php : tout doit être vert, et lisez « Points à corriger ».
  5. Clic droit sur installer_sauvegarde.bat > Exécuter en tant qu'administrateur. COPIEZ ensuite
     c:\xampp\cta_secret\sauvegarde.key sur une clé USB rangée à part : sans cette clé, les sauvegardes sont illisibles.
  6. Lisez DURCISSEMENT.txt et appliquez-le (mot de passe root, phpMyAdmin local seulement, HTTPS).
  7. Ouvrez http://localhost/cta/ . Premier accès : comptes « Médecin-chef », « Administrateur », « Responsable caisse »,
     « Responsable pharmacie », « Agent RH », « Agent PTME », « Agent CNAMGS », « Agent IDEP » ; mot de passe provisoire
     = valeur de « mot_de_passe_initial » dans config.php (par défaut cta2026 : CHANGEZ-LA dans config.php avant la
     première utilisation). Chacun doit choisir son mot de passe personnel à la première connexion (8 caractères,
     lettres et chiffres). Renommez ou désactivez les comptes dont vous n'avez pas besoin (Paramètres).

MISE À JOUR depuis la version 13 (vos données sont conservées)
  1. Sauvegardez : phpMyAdmin > Exporter la base cta (ou sauvegarde_script.bat de la v13).
  2. Dans c:\xampp\htdocs\cta : SUPPRIMEZ l'ancien index.html, puis copiez les fichiers de la v14 SAUF config.php
     (ne l'écrasez jamais) et SANS réimporter base_cta.sql.
  3. Dans config.php, ajoutez si absentes les lignes mot_de_passe_initial, session_heures, forcer_https,
     copie_externe, sauvegarde_jours (voir le config.php fourni).
  4. Ouvrez l'application : le schéma passe tout seul à la version 2. Les comptes existants sont repris avec leurs
     mots de passe actuels (ils sont convertis au nouveau format à la première connexion) ; l'ancien journal d'audit
     est repris tel quel, chaîne comprise ; les anciennes empreintes sont effacées du document et de l'historique.
  5. Les données de démonstration déjà saisies en v13 restent dans la base : si elles ne doivent pas rester, il faut
     repartir d'une base neuve (base cta supprimée puis réimportée) AVANT la mise en service réelle.
  6. Lancez installer_sauvegarde.bat (remplace l'ancienne tâche « Sauvegarde CTA »).

DROITS (appliqués par le serveur)
  Médecin-chef : tous les documents, journal, comptes des postes.   Administrateur : comptes, journal, sauvegardes (aucune
  donnée de soins).   Caisse / IDEP : base patients + caisse.   Pharmacie : pharmacie.   PTME : PTME + pharmacie (lecture
  des articles).   RH / CNAMGS : RH/CNAMGS.   Limite connue : à l'intérieur d'un module, le serveur ne filtre pas patient
  par patient (l'agent IDEP ne voit que « ses » patients grâce à l'écran, pas grâce au serveur) : cela demande la
  réécriture en tables séparées (étape suivante, voir plus bas).

SAUVEGARDE ET RESTAURATION
  - Tous les jours à 13h30 : fichier chiffré c:\xampp\cta_sauvegarde\cta_AAAA-MM-JJ_HHMMSS.enc, 60 jours conservés
    (sauvegarde_jours). Pour une copie hors de l'ordinateur : renseignez « copie_externe » dans config.php
    (ex. 'E:\\Sauvegardes_CTA' pour une clé USB ou un disque réseau).
  - L'ordinateur éteint à 13h30 : la tâche s'exécutera dès qu'il sera rallumé si vous cochez « Exécuter dès que possible »
    dans le Planificateur (propriétés de la tâche > Paramètres).
  - Restaurer : fermez l'application, puis  restaurer.bat "c:\xampp\cta_sauvegarde\cta_....enc"  (une copie de
    sécurité de l'état actuel est faite avant). Faites un essai de restauration sur une copie du serveur une fois par trimestre.
  - Export JSON (médecin-chef/administrateur) : menu Sauvegardes de l'application. Non chiffré : à manipuler avec soin.

PROTECTION DES DONNÉES DE SANTÉ
  - Aucune copie de données dans le navigateur au-delà du fonctionnement normal : la copie miroir locale est supprimée.
  - Chaque consultation de dossier est tracée (qui, quand, quel dossier). Contrôlez le journal régulièrement.
  - Durée de conservation des dossiers : à fixer par la direction (obligations légales gabonaises à vérifier). Le
    logiciel ne supprime jamais de dossier automatiquement ; seuls les historiques techniques (60 jours) et les
    sauvegardes chiffrées (60 jours) sont purgés.
  - Chiffrez le disque du serveur (BitLocker) : voir DURCISSEMENT.txt.

CE QUI N'EST PAS ENCORE FAIT (honnêteté)
  - Stockage en tables séparées (patients, reçus, stocks, factures) : les données restent des documents JSON par module
    (table cta_kv). Le serveur contrôle les droits par module, versionne chaque écriture et numérote les reçus, mais ne
    verrouille pas encore ligne par ligne. C'est un chantier à part (réécriture des quatre modules).
  - CSP « stricte » (sans script intégré) impossible tant que les modules sont intégrés dans la page : une CSP
    protectrice (pas de chargement externe, pas d'inclusion par un autre site) est déjà en place.
  - Testé automatiquement avec PHP + SQLite (droits, comptes, journal, reçus, sauvegarde/restauration). L'installation
    sur un vrai XAMPP/MySQL n'a pas pu être exécutée ici : au premier essai, ouvrez etat.php et envoyez-moi toute
    erreur affichée ou le fichier logs\cta_erreurs.log.
  - Mise en ligne sur Internet : déconseillée avec XAMPP/Windows. Pour cela, un petit serveur Linux (Apache ou Nginx
    + MariaDB) avec HTTPS est préférable ; le code PHP est le même.

DÉPANNAGE
  - « Serveur de données injoignable » : Apache/MySQL arrêté, mauvais identifiants dans config.php : voir etat.php.
  - Compte verrouillé (5 échecs, 5 minutes) : attendre, ou demander au médecin-chef de réinitialiser le mot de passe.
  - Session expirée : un bandeau propose de se reconnecter, les modifications en attente repartent ensuite.
  - Page ancienne : Ctrl + F5.

--- NOUVEAUTES (version 1.0, mise a jour du 17/11) ---
- Module 5 Laboratoire : creez un compte au poste "Laboratoire" (Parametres > Utilisateurs). Il ne voit que le stock des reactifs.
  Le serveur lui-meme ne lui transmet que les reactifs (pas de patients, ARV ni autres produits) et n'accepte de lui que des modifications de reactifs.
  Sur une base existante, le compte n'existe pas encore : ajoutez-le dans Parametres.
- Stock : chaque entree forme son propre lot ; "Modifier" sur un lot corrige produit / lot / quantite / peremption (motif obligatoire).
- Dispensation : seuls les produits en stock sont proposes. Tous les produits sont tries par ordre alphabetique.
- Serveur injoignable : banniere rouge, saisies conservees sur le poste et renvoyees automatiquement au retour du serveur.
Mise a jour : remplacer app.html, le dossier assets et common.php ; garder config.php ; Ctrl+F5 sur les postes.
- Dette CNAMGS : 2026 est en saisie manuelle (comme 2025) ; la gestion automatique commence en 2027. Les depots deja calcules pour 2026 sont repris comme point de depart et restent modifiables mois par mois.
- Base patients commune : la caisse et la pharmacie alimentent la meme base (un seul n de dossier par patient, jamais en double).
  Caisse : un ancien patient a deja son n de dossier ; pour un nouveau patient le n est facultatif (la fiche porte alors SN-0001, SN-0002... = n a attribuer).
  Pharmacie, onglet Patients : le pharmacien saisit le vrai n dans la fiche, puis dispense. Le bouton "Nouvelle fiche" sert seulement a un patient non passe par la caisse (n obligatoire, informations completes).
  Le responsable de la pharmacie peut corriger un n de dossier errone : il change partout (base, caisse, PTME, registre). Un n deja pris est refuse.
- Identite partagee PTME / pharmacie / caisse : nom, telephone et sexe sont lus dans la base commune. Une modification faite a un endroit apparait partout. La PTME ne reecrit jamais une fiche existante avec une ancienne valeur.
- Suppression d'une fiche (onglet Patients, bouton Supprimer) : sans justificatif, avec confirmation et trace dans l'audit. Les recus et dispensations deja faits restent dans l'historique.
- Aucun doublon : un n de dossier deja pris est refuse ; un meme nom (casse et accents ignores) sous un autre n est refuse a la creation (pharmacie, caisse, PTME) ; une mere ne peut avoir qu'une fiche PTME.
- Dispensation : apres la creation d'une fiche depuis la dispensation, la fiche du protocole s'ouvre tout de suite.
